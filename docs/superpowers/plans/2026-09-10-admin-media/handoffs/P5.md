## Review regressions added (this session)

Two review findings were confirmed as real defects and two test-coverage gaps were closed.

**1. Managed playback always resumed from 0 (HIGH, code fix).**
`JdbcMediaSessionRepository.resumePosition` filtered on `session_id` in addition to
`user_id`/`movie_id`/`media_version_id`. A grant always creates a brand-new session, which by
definition owns no progress row, so every managed grant answered `resumePositionSeconds = 0`.
The filter is gone; the viewer's single `(user_id, movie_id)` progress row is now resolved by the
pinned `media_version_id`, which is what keeps a replacement activation from resuming into the old
cut. New regression test:
`MediaTokenTest.progressResumesAcrossSessionsForTheSameVersionAndIsNotInheritedByANewVersion`
asserts 0 on the first grant, 30 on a second grant for the same version, 0 after the active pointer
moves to a newer version, and that stored progress is never rewritten by activation.

**2. The browser smoke never exercised the real player or the real CSP (HIGH, harness fix).**
The previous smoke wrote its own HTML page and configured HLS.js inline, so it could not see that
`frontend/nginx.conf` pinned `connect-src 'self'` or that the frontend image was built without any
media origin at all. Both are now real defects found by the rewritten smoke:
`frontend/nginx.conf` was replaced by `frontend/nginx.conf.template` (rendered at container start by
`frontend/docker-entrypoint.d/05-render-nginx-config.sh`, which substitutes only `MEDIA_ORIGIN` and
writes to `/tmp` so the service stays read-only), the frontend `Dockerfile` takes a
`VITE_MEDIA_BASE_URL` build argument, `compose.local.yml`/compose.p5.yml pass both, and
`attachPrivateHls` now joins the backend's root-relative `/hls/...` path onto the configured media
origin and fails loudly when the origin is missing instead of issuing an unauthenticated request
against the API origin. `tests/media-pipeline/test_playback.py` drives the built React app through
Nginx against a genuinely cross-origin gateway and asserts the CSP, the bundle, the bearer-header
origin scoping, the decoded stream and the unauthenticated 401.

**3. P5-A rejection matrix and refusal invariance (MEDIUM, test coverage).**
`publishRejectsIncompleteMetadataAndNonReadyMedia` now covers an empty synopsis (not just a missing
genre) and asserts the movie revision, catalog revision, audit trail, `published` flag and
`media_publication` are untouched by every refusal.
`publishRejectsArtworkThatIsForeignUnreadyOrOfTheWrongKind` adds artwork of the same movie whose
processing job has not succeeded, a BACKDROP offered as the poster, a POSTER offered as the
backdrop, and the cross-movie case, each asserting nothing was promoted into the public namespace.
`anAlreadyPublishedMovieSurvivesARefusedPublishUntouched` proves a refused publish on a published
movie leaves the previous active version, runtime, artwork pointer, revision, catalog revision,
audit trail and promotion log exactly as they were.

**4. Happy path atomicity (MEDIUM, test coverage).**
`aFailureAfterPromotionRollsBackLifecycleProjectionAuditAndPromotionLog` injects a PL/pgSQL trigger
that raises on the `audit_event` insert - after the lifecycle/active-version/projection update and
before the catalog revision bump - and asserts lifecycle, `published`, active version, manifest
pointer, artwork pointer, movie revision, catalog revision, audit count and `media_publication` all
keep their pre-command values. The trigger and function are dropped in a `finally`.

**5. Lifecycle and token negative branches (MEDIUM, test coverage).**
`archivedMoviesDenyPlaybackDirectlyAndRestoreNeverRepublishes` adds a direct denial assertion while
the movie is `ARCHIVED` (viewer grant and viewer refresh), then restores and proves the movie stays
`UNPUBLISHED` with the previous active version; the ADMIN preview session is also shown to survive
the movie's publication state by design.
`MediaTokenTest.anExpiredSessionIsDeniedForBothRefreshAndProgress` covers session expiry for
refresh and progress.
`MediaTokenTest.previewRefreshStaysAdminOwnedAndStopsWhenTheRoleIsRevoked` covers a successful
preview refresh, a viewer denied on the admin refresh endpoint, another administrator denied on
somebody else's preview session, the viewer endpoint refusing a preview session, and refresh denied
after the ADMIN role is revoked while the login token is still valid.

## The one local browser smoke (P5-I)

`tests/media-pipeline/test_playback.py` drives the real stack from `compose.p5.yml`: create a managed
movie, upload a synthetic 6s H.264/AAC video plus poster and backdrop through the private multipart
path, let the RabbitMQ worker produce READY output, publish (promoting only validated artwork), and
then load the production React build at `/watch/{movieId}` in headless Chrome. The web app is
published at `http://127.0.0.1:18081` and the gateway runs on the host at `http://127.0.0.1:8899`, so
the media origin is genuinely cross-origin from the page. The run asserts:

- the Nginx `Content-Security-Policy` names the configured media origin in `connect-src`;
- the built assets (including the lazily loaded player chunk) embed that same origin, and the player
  resolves the backend's root-relative HLS path onto it;
- the app's own HLS.js transport sends the media bearer header to the gateway for the manifest and
  every segment, the CORS preflight is answered 204 without a token, and the gateway (which answers
  200 only for a verified, path-bound token) serves them;
- the player reaches `readyState >= 3` with a decoded frame and advancing `currentTime`;
- no media or access token is written to browser storage;
- the same canonical manifest fetched without a token is refused with `401`.

The gateway in that run is `media-gateway/p5-gateway-node.mjs`, which bundles
`media-gateway/src/index.ts` with esbuild and serves it from a Node HTTP server whose R2-compatible
`DELIVERY` binding reads the Compose MinIO delivery bucket over plain HTTP, plus the smoke-only
`GET /__smoke/requests` journal (method, path, whether `Authorization` was present, status - never a
token value). Every authorization, path-binding, range and response decision is the production
gateway code; only the runtime differs from Cloudflare. `wrangler dev` was tried first and abandoned:
its local R2 store is a second, empty bucket, and seeding Miniflare's store needed extra moving parts
for no additional evidence.

## Diff/contract review findings

- Media tokens use a dedicated RS256 key pair (`app.media.signing.*`), audience `lvfast-media`,
  issuer `lvfast-media-backend`, `jti`, `nbf == iat` and a maximum five-minute lifetime; the gateway
  verifies issuer, audience, every required claim and the exact slash-terminated prefix before any
  storage read.
- `MoviePublicationService` refuses non-READY or cross-movie media and artwork, incomplete metadata
  and missing genres before touching the projection, and writes lifecycle, active version, runtime,
  artwork pointers, the compatibility projection, the catalog revision and the audit row in one
  transaction. Publication and activation are idempotent on `Idempotency-Key`.
- Activation changes only the active pointer; existing sessions keep their pinned `media_version_id`
  and their refreshed token is issued for the pinned attempt prefix. Unpublish/Archive deny new
  sessions and refresh; Restore returns UNPUBLISHED and never republishes.
- Resume is a viewer-level property of one pinned version, not of one playback session: the unique
  `(user_id, movie_id)` progress row is keyed by `media_version_id`, so closing the player and
  reopening it resumes the stored position while activating a replacement starts the new cut at 0.
- Managed playback is only ever authorized against the configured media origin. The backend answers a
  root-relative `/hls/...` path, the bundle joins it onto `VITE_MEDIA_BASE_URL`, the CSP names the same
  origin as `MEDIA_ORIGIN`, and a missing origin is reported as a player error rather than degraded
  into an unauthenticated request against the API host.
- Only validated artwork is copied into `public-artwork/{assetId}/image.jpg`; raw artwork, source
  uploads and every `hls/**` object stay behind the gateway.
- No signed URL, JWT, storage credential or source key appears in a client-facing projection, a log
  line or the diff. The test-only media key pair under `backend/src/test/resources/test-keys` is
  committed on purpose and used only by tests; `.env.example` documents that both key pairs must be
  mounted in a deployment.
