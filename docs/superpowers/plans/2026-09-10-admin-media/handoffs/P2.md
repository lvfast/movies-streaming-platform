## Focused red evidence

- `DirectUploadHttpTest`: the completion method initially failed (2 failures) with HTTP 500 — the
  `upload_session.job_id` foreign key was violated because `markCompleted` set `job_id` before the
  `media_job` row was inserted. The fix reordered `finalizeUpload` to insert the job first, then
  link `job_id`, keeping the guarded COMPLETING-to-COMPLETED transition as the exactly-once gate.
- `MediaSchemaTest` and `S3MediaObjectStoreTest` describe new schema/adapter units; both were
  introduced with their production code and verified green (constraints rejected invalid states,
  the adapter completed a real local multipart upload).

## Diff/contract review findings

- Storage network calls (initiate, sign, list, complete, head, abort) are kept outside database
  transactions; multi-statement writes run inside a `TransactionTemplate`, and completion inserts
  `media_job` before linking `upload_session.job_id` to satisfy the FK.
- Exactly-once is enforced by the guarded `OPEN -> COMPLETING -> COMPLETED` transition plus the
  `uq_media_job_active_*` partial unique indexes; a repeated completion reconciles via
  `HeadObject` (declared size + `resumefingerprint` metadata) and returns the same job.
- `upload_session.job_id`, `media_version.source_key` and `media_asset.source_key` keep the
  backend-owned `source/{movieId}/{uploadId}/original` key; raw filenames never appear in keys and
  no storage credential is returned to a browser.
- The local MinIO overlay uses `minioadmin`/`minioadmin` (well-known local-only defaults, matching
  the existing `.env.example` local Postgres password convention); no real secret, signed URL or
  JWT appears in the diff.
- OpenAPI gained `/admin/movies/{movieId}/uploads`, `/admin/uploads/{uploadId}` and its
  `parts`/`part-urls`/`complete`/`abort` subpaths plus `UploadInput`, `UploadSession`,
  `UploadedPart`, `PartSignRequest`, `SignedPart` schemas; `OpenApiContractTest` asserts them.

## Deferred items added to post-MVP

- Concurrent same-key create can surface 409 instead of replaying; sequential replay returns the
  identical session.
- Concurrent abort/complete on one OPEN session: exactly one guarded transition wins; the loser can
  see 409/503.
- Completion validates the Idempotency-Key header but deduplicates via state + HeadObject, not an
  `operation_request` row.
- A failed create transaction can orphan an already-initiated multipart upload (best-effort abort;
  storage lifecycle reclaims the rest).
