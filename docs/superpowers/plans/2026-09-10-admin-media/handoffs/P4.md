## Diff/contract review findings

- Retry delays are exactly 60s / 300s / terminal per the contract; only `STORAGE_UNAVAILABLE`,
  `PROCESS_TIMEOUT` and the backend-detected `LEASE_LOST` recovery code are retryable.
- `LEASE_LOST` is used solely for backend-detected lease expiry (worker death), never emitted as a
  worker-reported failure, so the worker-reported "only storage and process-timeout retry" rule is
  unchanged.
- The result inbox remains the dedupe log; `event_id` uniqueness dedupes duplicates, the
  current-attempt check fences old attempts, and `last_sequence` (reset to 0 on claim) fences
  out-of-order progress. Terminal transitions stay guarded by `state='RUNNING'`.
- Manual retry creates a new job id for the retained source, resets the target FAILED→QUEUED/STORED,
  appends one outbox command, records an audit event and replays on the same idempotency key.
- The harness uses only well-known local-only credentials (`minioadmin`, `media-test`,
  `worker-test-credential`) and publishes its own host ports/project name; it is discarded with
  `down -v`. No signed URL, JWT or storage credential appears in the diff.
