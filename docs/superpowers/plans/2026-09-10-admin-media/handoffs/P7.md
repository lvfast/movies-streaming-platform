## Review fixes applied (review round)

All nine reported items were verified against the code and fixed; each behavioral fix has a
regression test that was observed red before the fix.

1. **Attach BACKDROP did not move the backdrop pointer** — `attachArtworkCas` passed the `poster`
   flag to all four `CASE` expressions, so a BACKDROP request only bumped the revision. Fixed by
   passing the complementary flag for the backdrop columns. Regression:
   `AdminArtworkHttpTest.attachesBackdropWithoutDisturbingThePosterPointer` (was red:
   `backdrop_asset_id` unchanged).
2. **"Preview selected" previewed the active version** — the review page ignored the selected
   version and the backend had no way to request one. `MoviePublicationService.preview` now accepts
   an optional `mediaVersionId` (validated as a READY version of the movie, else 409), the controller
   accepts an optional `PublishRequest` body, `openapi.yaml`/client were regenerated and
   `AdminApi.previewMovie(movieId, mediaVersionId?)` sends it. Regression:
   `PublicationPlaybackTest.previewsTheRequestedReadyCandidateAndFallsBackToTheActiveVersion` (was
   red) and the admin-media preview assertion now requires the selected version id.
3. **Activate could target the active version** — `PublicationActions` gained `canActivate`; the
   button is disabled unless the selected version is the candidate, and `runCommand` refuses
   otherwise. Regression: `admin-media.test.tsx` "activates only a selected replacement candidate".
4. **Audit retry filter used wrong values** — the UI now offers `JOB_RETRIED`/`MEDIA_JOB` (and
   `APP_USER`), matching `JobRetryService`/`AdminRoleCommand`. Regression: filter-option test asserts
   the values.
5. **Polling did not stay stopped and could double-loop** — `useJobPolling` now has terminal
   `stopped` and single-flight `running` guards; `visibilitychange` only re-times the next poll and
   never restarts a stopped job or starts a second loop mid-request. Regressions: terminal +
   visibility test and mid-request visibility test.
6. **Resume journal was not scoped to the open movie** — the upload page only offers/resumes a
   journal entry whose `movieId` matches the route. Regression: "only resumes a journal entry that
   belongs to the open movie".
7. **Jobs page recovery** — list retry now increments a reload token so the effect reruns, and each
   retry action generates a fresh idempotency key (reused only by its own response-loss retry).
   Regressions: list-retry test and fresh-key-per-action test.
8. **Audit redaction was top-level only** — `JdbcAuditQueryRepository` now redacts recursively
   through nested objects and lists. Regression:
   `AdminAuditHttpTest.redactsSecretLikeFieldsInsideNestedObjectsAndLists` (was red).
9. **Flaky fingerprint test** — the 3-MiB fixture is now 2 MiB + 1 byte with a 15-second timeout;
   the file passed three consecutive focused runs. This is a test-harness fix, not a product change.

Test-harness note: adding a tenth test to `PublicationPlaybackTest` pushed the class past the
10-per-minute auth rate limit, so its `@BeforeEach` now clears the `rate:auth:*` Redis keys; without
this the next method's registration failed with 429.

## Diff/contract review findings

- The three new endpoints sit behind the existing `/api/v1/admin/**` current-role authorization.
- `GET /admin/audit` redacts any secret-like key (`secret`, `token`, `password`, `credential`,
  `authorization`, `api-key`, `private-key`, `signing-key`, `key`) **recursively through nested
  objects and lists** in stored `before`/`after` payloads before serializing; responses are paged by
  descending event id.
- `POST /admin/movies/{movieId}/preview` accepts an optional `mediaVersionId`; a requested version
  must be a READY version of the same movie (409 otherwise), and omitting it keeps the active/latest
  behavior. The review page sends the selected version so candidate inspection is real.
- `POST /admin/movies/{movieId}/artwork` requires `If-Match`, validates the asset is a READY asset
  of the same movie and kind, moves only the requested pointer, bumps the movie revision, audits
  `MOVIE_ARTWORK_ATTACHED` and promotes to the public namespace when the movie is already
  PUBLISHED. No permanent delete exists anywhere.
- `POST /admin/assets/{assetId}/preview` returns a 60-second presigned private read URL only for a
  validated READY asset, and only to an authenticated current ADMIN.
- The upload manager persists just `{uploadId, movieId, fingerprint, fileName, sizeBytes}`, sends
  storage PUTs with `credentials: 'omit'` and only signed headers, caps concurrency at four,
  resumes from authoritative `ListParts`, refreshes expired part URLs with bounded retry, and keeps
  "Finalizing" until a COMPLETED session carries a job id.
- No secret, signed URL, JWT or storage credential appears in the diff or test logs; the presign
  test uses placeholder credentials.
