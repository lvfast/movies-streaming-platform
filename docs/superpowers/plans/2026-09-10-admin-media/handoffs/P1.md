## Direct neighboring tests and why they were affected

  `AccessTokenIssuer`/`AuthService`/`AuthController` public shapes changed to carry roles.
- `Task4SecurityHttpTest`, `CatalogSecurityHttpTest`, `ObservabilitySecurityTest`: `SecurityConfiguration`
  gained the `AdminAuthorizationManager` bean, so their test configs now supply a `RoleService`.
- `Task4RedisDegradedTest`: the `AccessTokenIssuer.issue` signature changed.
- `Task4AuthenticatedFlowTest`: registration/login path now grants USER and exposes roles.
- `CatalogTestcontainersTest`: the catalog cache keys became revision-namespaced.
- `CatalogServiceTest`, `ArchitectureTest`, `MediaStreamingApplicationTest`: catalog cache interface,
  package/module structure and application wiring changed.

## Diff/contract review findings

- `UserAccount.java` was intentionally left unchanged: roles live in `user_role` and are read/written by
  `JdbcRoleService`, so no JPA field was required.
- `CatalogService.java` was intentionally left unchanged: revision namespacing is internal to
  `RedisCatalogCache`/`CatalogRevisionRepository` and the public read path is unchanged.
- `application.yml` was intentionally left unchanged: the operator command is a runtime argument
  (`--app.ops.roles=...`) with an empty default, and no static configuration was required.
- `AdminRoleCommand` is a plain `@Component` whose `run()` no-ops when `app.ops.roles` is blank, rather
  than a `@ConditionalOnProperty` bean, so its grant/revoke methods stay directly testable; the non-web
  invocation is documented in `docs/runbooks/admin-bootstrap.md`.
- OpenAPI gained `/admin/movies`, `/admin/movies/{movieId}`, `/admin/genres`, the `MovieInput`,
  `AdminMovie`, `AdminMoviePage` and `GenreOption` schemas, and `roles` on `User`; `OpenApiContractTest`
  now asserts those additions.
- No secrets, signed URLs, JWTs or storage credentials appear in the diff.
