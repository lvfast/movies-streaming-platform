## Focused red evidence

- `ArtifactVerifierTest.acceptsAValidTranscodeArtifact` initially failed (declared `index.m3u8` size did
  not match the actual playlist bytes); fixed the fixture to compute the size from the real playlist.
- `ProcessingHappyPathTest.acceptsCurrentAttemptResult` initially failed with a foreign-key violation:
  `inbox_event.attempt_id` referenced `media_job_attempt`, so a stale/nonexistent attempt could not be
  recorded and ignored. `V4` drops that FK; the current-attempt gate is service logic, so late or
  malformed results are recorded then ignored rather than rejected at the storage layer.
- `VideoProbeTest.probesActualTracksDurationAndDimensions` initially hit an NPE because the HDR check
  called `List.contains(null)`; fixed to guard the null `color_transfer`.
- `ArtworkProcessorTest.rejectsCorruptInput` initially failed because ffprobe reports a 0x0 mjpeg
  stream for undecodable bytes; fixed `ArtworkProcessor` to reject non-positive decoded dimensions.
- The local worker smoke surfaced an `INTERNAL_ERROR` (`Unexpected worker failure`): the executor did
  not create its `output` directory before invoking FFmpeg, so `ProcessBuilder` failed to start.
  Fixed `DefaultJobExecutor` to create the output directory (and added logging for the failure
  branches). This path was not caught by the unit tests because `HlsEncoderTest` creates the output
  directory itself.

## Local happy-path evidence (compose, real worker)

The full stack (`compose.yml + compose.local.yml + compose.media.local.yml`) was built and run with a
real RabbitMQ 4 broker, MinIO and the transcoder worker, and the required journey passed end to end:

```text
scripts/happy-path.ps1  (HTTP upload -> complete -> outbox -> RabbitMQ -> worker -> READY -> decode)
  -> JOB: SUCCEEDED  VERSION: READY
  -> DECODED CODECS: h264 aac

scripts/worker-smoke.ps1    (video -> READY HLS)      -> JOB: SUCCEEDED  VERSION: READY
scripts/artwork-smoke.ps1   (poster -> READY artwork) -> JOB: SUCCEEDED  ASSET: READY, image.jpg 600x900 mjpeg
```

The HTTP journey initially failed because Docker Desktop did not publish the MinIO host port: MinIO
was attached only to the `internal: true` application network, so its `ports:` binding never became
reachable from the host (`docker port` returned empty). Adding the `edge` network to the MinIO service
and switching the part PUT to `System.Net.WebClient.UploadData` (Windows PowerShell 5.1 has a
`byte[]`-body bug in `Invoke-WebRequest`) fixed it. `S3_BROWSER_ENDPOINT` is now `http://127.0.0.1:9000`
for an unambiguous IPv4 host path.

## Diff/contract review findings

- `messaging` has no dependency on `media`; the slice graph remains `media -> messaging` only, so the
  module-cycle check stays green.
- Claim/heartbeat are machine-authenticated (`WorkerCredentialFilter`, constant-time comparison) behind
  `/internal/v1/**`; a human login JWT never satisfies these endpoints. The claim response carries only
  the backend-issued attempt/source/output parameters and never a storage credential.
- The worker's dependency tree contains no JDBC/JPA/hibernate/database driver (`dependency:tree` grep
  returned nothing relevant; only Apache HTTP Core 5's unrelated `httpcore5-h2` module matched the "h2"
  pattern).
- Storage network calls stay outside database transactions; claim/heartbeat/result writes run inside a
  `TransactionTemplate`, and the exactly-once claim is a guarded `QUEUED/RETRY_WAIT -> RUNNING` update.
- The `isAck()` deprecation warning from `CorrelationData.Confirm` is a Spring AMQP 4 warning, not an
  error; publisher confirms are configured via `spring.rabbitmq.publisher-confirm-type: correlated`.
- No secrets, signed URLs, JWTs or storage credentials appear in the diff.

## Deferred items added to post-MVP

- Result inbox insert + processing + manual ack are not one atomic unit, so a crash between inbox insert
  and processing would drop a redelivered duplicate (ack happens after processing; the event_id unique
  index would skip the redelivery). Bounded retry and the recovery gate are P4's concern.
- Artifact object digests (`sha256`) are declared and schema-checked but not recomputed by the verifier
  in P3; only identity, prefix, playlist coverage and sizes are verified.
- EXIF orientation is normalized by FFmpeg's default JPEG decode (proved with an injected orientation-6
  fixture); no explicit per-orientation transpose matrix is applied in the worker code itself.
